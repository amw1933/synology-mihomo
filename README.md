# 群晖 NAS 部署 mihomo（Clash.Meta）：**旁路由版**，带中文网页管理台

> 在群晖上跑 **mihomo** 内核，**Container Manager 点三下**（或 SSH 一条命令）装好，
> 之后加机场、加节点、改策略，全在**中文网页管理台**里点。
>
> 🚪 **这台群晖可以当旁路由（网关）用**：在路由里把设备的**网关**指向群晖 IP，
> 设备什么都不用填，全部流量自动走 mihomo 按规则分流（国内直连、国外走节点）；
> 想单独用代理的 App，也照常可以填 `群晖IP:7890`。
> 原理、配置、常见坑见 **[旁路由模式.md](旁路由模式.md)**。
>
> 🔌 **单端口设计**：管理台 `/`、节点面板 `/ui/`、内核接口反代 `/clash/` **共用一个端口**（默认 `9090`），
> 路由器 / 防火墙只需放通这一个；内核控制接口收在 `127.0.0.1:9091`，**不对外**。

## 一分钟上手

> 前提：群晖 **DSM 7**（Container Manager 或 Docker 套件）。不需要公网 IP，也不需要改动群晖系统设置。

**方式 A · Container Manager（点几下，推荐新手）**

1. Container Manager → **项目** → 新增 → 名称 `mihomo`、路径 `/docker/mihomo`
2. 把仓库里的 **[docker-compose.yml](docker-compose.yml)** 整个粘进去（**一个字都不用改**）→ 完成
3. 浏览器打开 `http://群晖IP:9090` → 默认密码 `admin`（**登录后立刻改掉**）
4. 节点面板**已自动装好** —— 直接打开 `http://群晖IP:9090/ui/`，**不用填地址、不用填密钥**（零配置）
5. 「**机场**」粘贴订阅链接 → 点「**立即更新配置**」→ 完事

**方式 B · SSH 一条命令**

```bash
curl -fsSL https://raw.githubusercontent.com/amw1933/synology-mihomo/main/mihomo-install.sh -o /tmp/mh.sh
sudo SUB_URL='你的订阅链接' ADMIN_PASS='你要设的密码' bash /tmp/mh.sh
```

**想让它当旁路由（网关）**：在路由器里把设备的**网关**改成 `群晖IP`，**DNS 不用动**，
设备（电视盒子、游戏机这类不能填代理的）就自动全局走代理。原理与坑见 **[旁路由模式.md](旁路由模式.md)**。

## 兼容性 / 前提

| 项目 | 要求 | 说明 |
|---|---|---|
| DSM | **7.x** | Container Manager（或 Docker 套件）；6.x 未测试 |
| 架构 | x86_64 / arm64 | 内核镜像官方多架构，群晖两种都能跑 |
| TUN（旁路由用） | 内核有 `/dev/net/tun` | 大多数 DSM **自带**，无需设置；**万一没有，一键脚本会自动降级成"只提供 7890 代理端口"，不会安装失败** |
| 系统转发 | `net.ipv4.ip_forward=1` | 装了 Docker 默认就是 1（`sudo sysctl net.ipv4.ip_forward` 可查） |
| 群晖地址 | 建议**固定 IP** | 设备要把网关指向它，IP 一变就失效 |
| 端口 | 只需放通 **9090** | 代理端口 7890 可选；内核接口 9091 只绑本机、不对外 |

## 特点

- 🖱️ **两种部署方式**：Container Manager **粘一个 `docker-compose.yml`**（零修改、零上传） / SSH 一条命令
- 🚪 **旁路由模式**：设备**只填网关**就全局走代理，电视盒子、游戏机这类不能填代理的设备也能用（见 [旁路由模式.md](旁路由模式.md)）
- 🧩 **换机器直接粘**：compose 里没有任何写死的 IP，管理台自己识别宿主地址；装第二套改 `.env` 里的容器名即可
- 🔄 **改 IP / 加第二个 IP / 换机器都不用改配置**：地址都是自动识别的（已实测两个 IP 同时可用）
- 🖥️ **中文网页管理台**：状态、机场、节点、策略、工具五个页面，手机也能用
- 🔄 **内核一键更新**：运行状态卡里自动检测 mihomo 有没有新版（结果缓存 6 小时，不拖慢页面）；有新版会显示红标「有新版 vX.Y.Z」+「**一键更新内核**」按钮 —— 自动拉最新镜像并重建内核容器，配置 / 订阅 / 线路 / 端口都不动（代理中断 1~2 分钟）
- 🔌 **代理提供者独立出来**：机场订阅就是独立的 `proxy-providers`，换机场只动一处，
  所有策略组自动跟着变（面板「代理提供者」里能直接看到）
- ➕ **网页里直接加机场 / 加节点**：
  - 加机场 = 粘贴订阅链接（Clash 格式），支持多机场并存
  - 加节点 = 粘贴分享链接，支持 `vmess` / `vless`(含 reality) / `ss` / `trojan` /
    `hysteria2` / `hysteria` / `tuic` / `anytls` / `http` / `socks5`
- 🇭🇰 **地区三件套**：香港 / 日本 / 新加坡 / 美国 / 台湾 / 韩国，每个地区自动生成
  **手动(select) + 故转(fallback) + 自动(url-test)** 三个策略组
- 🎵 **TikTok / AI 默认走狮城**（香港上不了 TikTok），都能手动改；策略组结构/命名/图标与 CT200 参考实现一致
- 🎯 **规则集分流**：AI / 油管 / 谷歌 / GitHub / 电报 / TikTok / Netflix / 微软 / 苹果…
  按规则集自动分流，国内直连；也可**每条规则手动选** 直连 / 某个策略组
- 🔄 **保存即生效**：加机场、加节点、改策略、存规则 → 自动更新配置，
  页面弹窗提示「正在更新配置…」→「✅ 更新完毕」，失败也有中文原因
- ⏰ 定时自动更新（默认每天 04:00，自动同步机场订阅）
- 🩺 一键健康自检 7 项（容器 / 配置 / 代理 / 面板接口 / 磁盘 / 程序文件 / 定时任务）
- 🌐 节点面板 **metacubexd**（管理台里一键安装）
- 💾 配置备份 / 回滚、运行日志、端口和地址随时可改

## 快速开始

### 方式一：Container Manager（纯网页，**一个文件粘一次就跑**）

1. **File Station**：在 `docker` 共享文件夹下新建 `mihomo`，里面再建一个 **`etc`** 子文件夹
   （`etc` 必须存在 —— 它是内核配置目录的挂载点，缺了会报 `Bind mount failed: … does not exist`）
2. **Container Manager → 项目 → 新增**，项目名 `mihomo`，路径选 `/docker/mihomo`，
   来源选「创建 docker-compose.yml」，把 [docker-compose.yml](docker-compose.yml) 整段粘进去
   → **一个字都不用改**（内核走 host 网络 + TUN：代理 **7890** / 管理台 + 面板 **9090**）
3. 等 1~2 分钟，浏览器打开 `http://群晖IP:9090`，默认密码 **`admin`**
   （**登录后请立刻到「工具」页改掉**，页面顶部也会红字提醒你）
4. 「机场」粘贴订阅链接 → 保存（自动更新配置）；节点面板开 `http://群晖IP:9090/ui/`（地址和密钥界面里都已预填）

> **换台群晖（别的机器）也一样**：`docker-compose.yml` 里**没有写死任何 IP**，
> 管理台自己识别宿主地址，所以同一份文件粘到哪台都能跑。
> 想改密码 / 容器名 / 管理台端口：在同目录放一个 [.env](.env.example)，compose 文件不用动。

详细步骤见 **[群晖ContainerManager部署教程.md](群晖ContainerManager部署教程.md)**

### 方式二：SSH 一条命令

```bash
sudo -i
curl -fsSL https://raw.githubusercontent.com/amw1933/synology-mihomo/main/mihomo-install.sh | bash
```

带订阅链接和管理台密码：

```bash
curl -fsSL https://raw.githubusercontent.com/amw1933/synology-mihomo/main/mihomo-install.sh | \
  SUB_URL='你的订阅链接' ADMIN_PASS='你的密码' bash
```

详细步骤见 **[群晖SSH部署教程.md](群晖SSH部署教程.md)**

|---|---|---|
| 代理 | **7890** | HTTP / SOCKS5 同一个口，填到手机电脑上用 |
| 节点面板 | **9090** | `http://群晖IP:9090/ui/`，密钥 = 管理台密码 |
| 网页管理台 | **9090** | `http://群晖IP:9090` |


---

### 单端口架构（对外只有 `9090`）

| 路径 | 内容 |
|---|---|
| `/` | 网页管理台（改密码 / 加机场 / 加节点 / 更新配置 / 健康自检） |
| `/ui/` | 节点面板 metacubexd —— **开箱即用**：装好直接打开就是面板主页，不用填地址/密钥 |
| `/clash/` | 内核接口反代（面板自动调用，同样受密钥保护） |

- **`9091`** 是内核控制接口，只绑 `127.0.0.1`，**不对外**；所以路由器/防火墙只需要放通**一个 9090**
- **零配置**：打开 `/ui/` 直接进面板（管理台会按登录会话自动代填密钥）。万一出现设置页：地址填 `http://群晖IP:9090/clash`、**密钥留空**
- `7890` 仍是代理端口（App 里手动填代理时才用；旁路由模式下设备不需要它）

## 参数（SSH 安装脚本）

| 参数 | 默认值 | 说明 |
|---|---|---|
| `SUB_URL` | 空 | 机场订阅链接（Clash 格式） |
| `ADMIN_PASS` | 随机 | 管理台密码 / 面板密钥 |
| `MH_IP` | 自动识别 | 绑定 IP |
| `PROXY_PORT` / `PANEL_PORT` / `ADMIN_PORT` | `7890` / `9090` / `9090` | 三个端口 |
| `BASE_DIR` | `/volume1/docker/mihomo` | 安装目录 |
| `CT_PREFIX` | 空 | 容器名前缀（同机装第二套时用） |

## 目录结构

```
/volume1/docker/mihomo/
├── compose.yaml           # 编排文件（含端口、挂载、环境变量）

│   ├── ui/                # metacubexd 面板

├── backup/                # 配置备份（保留最近 10 份）
└── admin/
    ├── app.py             # 网页管理台
    └── Dockerfile
```

## 它是怎么工作的

- **机场** → 生成 `proxy-providers`，mihomo 自己按 `interval` 定时拉订阅（**节点不写进主配置**）
- **手动节点** → 生成 `proxies:` 条目，和机场节点混用
- **策略组** → 用 `use: [airport]` + `filter:` 正则从提供者里挑节点（地区三件套就是这么来的），
  手动节点用 `proxies:` 直接列出
- **改完配置** → 先 `mihomo -t` 校验，通过再走控制接口热重载，失败兜底重启容器

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 面板打开要填「连接到后端 / 密钥」 | 地址填 `http://群晖IP:9090`，**密钥填管理台密码** |
| 「代理提供者」显示 0 | 说明还没加机场，或管理台没生成过配置：去「机场」添加订阅并保存 |
| 容器一直重启 | 看日志：多半是配置为空（新装第一次管理台会自动写引导配置，等 10 秒） |
| 节点面板里节点不显示 | 机场订阅拉取失败（网络原因），到管理台看该机场的「节点数 / 更新时间」 |
| 改端口后连不上 | 「工具」里改完端口要等它自动重建容器，然后用新端口访问 |
